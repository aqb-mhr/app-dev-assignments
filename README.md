# Campus Lost & Found

Flutter app for posting and tracking lost and found items around IBA campus, backed by Cloud Firestore.

Assignment 3, Application Development for Mobile Devices (CSE-450). Branch: `feature/lost-found-firebase`.

## Features

| Requirement | Where |
|---|---|
| Real-time list via `.snapshots()` | `ItemRepository.watchItems()` + `StreamBuilder` in `item_list_screen.dart` |
| Search by title + status filter (All / Lost / Found / Claimed), working together | `logic/item_filter.dart`, search field and chips in the list screen |
| Add Item form writing to Firestore | `screens/add_item_screen.dart` |
| Race-safe "Mark as Claimed" with a Firestore transaction | `ItemRepository.markAsClaimed()` |
| Delete (with confirm and Undo) | `actions/item_actions.dart` |
| Detail screen that updates live | `screens/item_detail_screen.dart` (listens to the item's own document) |
| Seed the 8 sample items | "Load sample items" in the list's menu or empty state (`data/seed_data.dart`) |

## Setup

Requires Flutter 3.35 or newer and a Firebase project.

```bash
# 1. Generate the platform folders (keeps existing lib/ and test/ files)
flutter create . --project-name lost_found --platforms=web,android,windows,ios

# 2. Get packages
flutter pub get

# 3. Connect Firebase (install the CLIs once if needed)
#    npm install -g firebase-tools && dart pub global activate flutterfire_cli
firebase login
flutterfire configure        # overwrites lib/firebase_options.dart

# 4. Run
flutter run -d chrome
```

Then in the Firebase console:

1. **Firestore Database > Create database** (test mode is fine to start).
2. Optional but recommended: paste `firestore.rules` into **Firestore > Rules** and publish.
3. Launch the app and tap **Load sample items** to seed the `items` collection.

Android needs `minSdk 24` with the latest Firebase packages. If the build complains, set `minSdk = 24` in `android/app/build.gradle.kts`.

## Data model

Collection `items`, one document per item:

| Field | Type | Notes |
|---|---|---|
| `title` | string | |
| `category` | string | Bag, Accessory, ID Card, Electronics, Keys, Book, Clothing, Other |
| `location` | string | where it was lost or found |
| `status` | string | `Lost`, `Found` or `Claimed` |
| `description` | string | |
| `postedBy` | string | the poster's name |
| `createdAt` | timestamp | server timestamp on create |
| `claimedAt` | timestamp | set by the claim transaction |
| `previousStatus` | string | Lost or Found, set by the claim transaction |

Seed items use fixed ids (`seed-black-backpack`, ...) so seeding twice never duplicates them or resets a status.

## How "Mark as Claimed" stays consistent

```dart
_db.runTransaction((tx) async {
  final snap = await tx.get(ref);                 // read inside the transaction
  if (!snap.exists) return ClaimOutcome.notFound;
  if (status(snap) == Claimed) return ClaimOutcome.alreadyClaimed;
  tx.update(ref, {'status': 'Claimed', 'previousStatus': ..., 'claimedAt': serverTimestamp});
  return ClaimOutcome.claimed;
});
```

- If two people tap at the same moment, both transactions read the item as Found. The first commit wins; Firestore sees the document changed under the second one and retries it. On retry it reads `Claimed`, writes nothing and returns `alreadyClaimed`, and that user sees "Someone else already marked this as claimed".
- Repeated taps on the same device share one in-flight transaction, and the button is disabled while it runs.
- `firestore.rules` adds a server-side backstop: an update is only accepted if the stored status is not already `Claimed`.

## Project structure

```
lib/
  main.dart                  Firebase init, setup-error screen
  app.dart                   MaterialApp + theme
  firebase_options.dart      generated by flutterfire configure
  models/lost_item.dart      LostItem, ItemStatus, categories
  data/item_repository.dart  all Firestore reads/writes, claim transaction
  data/seed_data.dart        the 8 sample items
  logic/item_filter.dart     search + status filter, counts, sorting
  actions/item_actions.dart  claim / delete dialogs and snackbars
  screens/                   list, add item, detail
  widgets/                   status badge, item card, filter chips, empty state
  theme/app_theme.dart       Material 3 theme, status colours, item icons
test/                        unit + widget tests (fake_cloud_firestore)
firestore.rules
```

## Tests

```bash
flutter analyze

```

The tests run against `fake_cloud_firestore`, so they need no Firebase project. The fake does not simulate transaction contention between two clients; that guarantee comes from Firestore itself (and the rules above).
